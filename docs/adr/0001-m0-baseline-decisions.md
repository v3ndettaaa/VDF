# ADR 0001 — M0 baseline architecture decisions

Status: Accepted (2026-09-30)
Context: MASTER_PLAN.md §3, §5–§11. This ADR records the decisions taken while
implementing M0 so later milestones (and reviewers) know why the foundations
look the way they do.

## Decisions

1. **Framework-free UI with one observable store.** The DOM owns chrome only;
   `ui/state/store.ts` is a ~40-line immutable-snapshot store. No framework,
   no state library — the UI hot-path rule (MASTER_PLAN.md §5) is why.
2. **Rust 2024 edition, pinned toolchain 1.98.1.** `gen` became a reserved
   keyword in 2024; identifiers avoid it. The distro toolchain (Arch rust
   1.98.1) matches CI via `rust-toolchain.toml`, keeping local and CI builds
   identical without requiring rustup locally.
3. **Per-document-scoped object identity.** `ObjectId`/`PageId` are monotonic
   from a per-document `IdGenerator`; cross-document uniqueness is carried by
   `DocumentId`. Persistent identity is per document, not global.
4. **Transport abstraction before transport.** `vdf-render` defines
   `RenderTransport` (publish/invalidate) and `Rasterizer` traits in M0 with an
   in-memory implementation and a synthetic rasterizer. M1 plugs in the
   real binary transport without touching call sites.
5. **Atomic write discipline in M0, not M5.** `vdf_persist::atomic_write`
   (temp → flush → fsync → rename) lands with the first crate that could ever
   write user data, so nothing later grows a non-atomic write habit.
6. **Honest IPC absence.** The UI bridge fails loudly (`IpcUnavailableError`)
   outside the Tauri shell rather than stubbing responses; status text says so.
7. **AGPL-3.0-only.** MuPDF is AGPL; VDF inherits it. Recorded in
   MASTER_PLAN.md §3 and the LICENSE file.
8. **Golden vectors as the Rust↔TS contract.** `tests/vectors/affine-cases.json`
   is generated by a Rust test and consumed by a vitest test, so the TS mirror
   of Rust geometry cannot drift silently.

## Consequences

- M1 must replace `SyntheticRasterizer` with a MuPDF-backed rasterizer and
  implement a real `RenderTransport` — no trait changes expected.
- The per-document id scoping means serialized documents embed ids that are
  only meaningful within one document; recovery/replay never mixes documents.
- Any change to the traits above requires updating this ADR.
